## Learning Goal

Welcome!

Congratulations! You successfully read and understood the `README.md` instruction. 

You started up a Codespace and ran a shell script that created this issue off a remote template.

This tutorial will take you through quite journey.

### Opinionated tool stack

**Here's the contract: You will be introduced to a flavoured and opinionated tool stack, but in general, anything you do here, can also be done in similar or competing tool stacks. So even if this may not necessarily be your favorite choice of stack, try to disregard that sentiment for a while. Stay focused on the principles.**

You will get a deep dive into:

 - [ ] Using GitHub CLI
 - [ ] Creating fine-grained Personal Access Tokens (PAT) and setting up shared secrets in you repository
 - [ ] Define and use Devcontainers and run them both from your IDE and from GitHub CodeSpaces
 - [ ] Use Docker from your own PC to start your Devcontainers
 - [ ] You will create git aliases to enable easy access to advanced git features you want to use more often
 - [ ] Tweak git to read all your git settings from a repository shared configuration file - including all your aliases
 - [ ] Setting up githooks and lean, how to reuse them in your GitHub workflows and enforce Copilot to honor them too
 - [ ] Configure you workflow to work with a completely Pull-Request free flow that guarantees a non-breakable and pristine `main` branch
 - [ ] Use VS Code and install your linting tools not only as VS Code extensions, but at CLIs as well, and setup both to use the same configurations, version controlled in from your repo.
 - [ ] You will setup and configure the runner that Copilot uses in agentic mode, and you will enforce it to adhere to all your quality standards. Effectively make is safe to work with collaborative and spec-driven development
 - [ ] You will learn to setup Copilot, which is inheritably Pull-Request centric, to follow your flow which is carefully desinged to be trunk-based adn Pull-Request free.
 - [ ] You will write your own parameterized GitHub Actions and hereby set a definitive stop the frustrating copy'n'paste reuse in your declarative workflow files. And start reusing _for real_.

 There's probably more.

 For now, check the 3-5 most interesting learnings you look forward to obtain and drag them to the top of the list.
